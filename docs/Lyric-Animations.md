# 歌词切换动画

在「动态歌词」页的「歌词切换动画」选择效果，选择后自动保存。点击「在音响上试播当前动画」可试播三行文字，无需先播放音乐。试播期间暂停正常歌词推送，结束后恢复同步；离开页面会取消试播。

| 编号 | 进入 | 退出 |
| --- | --- | --- |
| 1 | 从底部往上 | 从底部往上 |
| 2 | 从中间扩散 | 从两边收缩 |
| 3 | 从左往右 | 从右往左 |
| 4 | 从底部往上 | 从顶部往下 |
| 5 | 从顶部往下 | 从右往左 |

默认使用第一组，QQ 音乐与网易云音乐共用此选项。「关闭动画」恢复原有居中静态或长句滚动。保留原有播放器、歌词时间偏移、缓存路径等设置。

同一首歌的相同歌词只推送一次，后台重新匹配歌词文件不会重播当前行的动画。切歌、换行、切换动画，以及主动重新同步或试播结束后，按需要更新屏幕。

网易云 InfLink 已提供可靠进度时，优先按时间轴选择当前歌词，不再让桌面窗口中的旧文字覆盖当前行。重新加载同一首歌的歌词文档也会保留进度外推，避免卡在第一句。

歌词接口按歌曲 ID 请求完整版本（`lv=-1/kv=-1/tv=-1`）。固定请求版本 1 会让部分歌曲返回空歌词；空内容不会作为成功结果缓存，暂时载入失败时每 10 秒自动重试。

## 发布目录回归检查

WinUI 的非 MSIX 程序也需要 `EnableMsixTooling=true` 才能完整发布 XAML / PRI 资源。
不要将漏带资源的新程序覆盖到旧安装目录，否则新代码会加载旧页面，在控件连接时崩溃。
项目默认启用此选项；本地覆盖安装前，先在独立的发布目录运行：

```powershell
dotnet publish src/PixelBar.App/PixelBar.App.csproj -c Release -r win-x64 --self-contained true -p:PublishSingleFile=false -o publish/app-install
./scripts/test-lyrics-page.ps1 -PublishDirectory publish/app-install
```

测试先检查旧桌面歌词干扰、连续换行、时间偏移、进度外推、拖动进度和版本 1 的空/完整接口响应，再短暂创建应用自身的测试窗口，分别构造和导航到歌词页两次，等待页面加载，检查设置没有变化后退出。
它不启用托盘或歌词推送，不发送 HID 数据，不操作其他窗口。异常写入日志，失败返回错误。
测试应直接运行发布目录中的程序，不能仅用 `dotnet build` 的输出代替。

## 协议与实测依据

本次 2026 款 A160（VID `2D99`，PID `A160`，屏幕集合 `MI_04/Col02`、UsagePage `FF14`）响应 `EC/EE` 查询，未响应 `ED/01` 查询。不能仅凭 PID 或年份推断使用 ED 协议。本实现使用与该设备兼容的 EC 协议；A106 的 EC 命令结构保持兼容，旧款未作实机回归。

2026-10-19 用户在 TempoHub 手动选择第二、第五组时，读取的设备返回体分别为 `01 F0 B4 C8 00 00 01 00 01`、`01 F0 B4 C8 00 00 01 00 04`。本地指令测试中，用户确认三行文字具有进入/退出动画。

每次推送包含以下顺序（以下为未填充至 64 字节的报文）：

1. **启用歌词叠层**：`2E AA EC EF 00 09 02 F0 B4 C8 00 00 01 FF FF FB`。
2. **选择第一组动画**：`2E AA EC EF 00 09 01 F0 B4 C8 00 00 01 00 00 FC`。末尾动画字段为 `0..4`，对应界面 `1..5`。
3. **发送歌词文字**：`EC/E8`，数据为 `0E 总UTF8长度 UTF8片段`。`0E` 是歌词来源，普通文字来源 `00` 会切回自创文字显示。

只设置动画不等于启用歌词叠层，这是此前“有设备但不显示新歌词”的关键区别。关闭动画时先发送 action `02` 的关闭报文，再发送普通文字布局和文字。

每个报告 64 字节，以 `2E` 开始。外层长度为本帧载荷长度，校验为除 `2E` 外各有效字节之和的低 8 位。歌词一帧最多 55 字节 UTF-8，长句按相同来源与总长度分包，总长度最多 255 字节；客户端按 Unicode 标量安全裁剪，避免截断表情符号。

协议字段依据本机已安装 TempoHub 的数据结构、实际设备返回报文与用户目视确认实现；不包含官方程序提取物、本地用户路径或设备唯一实例路径。
